# Terraform Configuration для SCIFiC

Проект був розроблений в рамках дипломної роботи та призначений
для розгортання інфраструктури в хмарі Hetzner. Ця інфраструктура
складається з одного віртуального приватного сервера,
призначеного для хостингу на ньому вебсайта конференції SCIFiC. 


## Перед початком

В цьому проекті замість Terraform використовувався OpenTofu. 
Але, якщо є бажання використовувати саме Terraform, потрібно 
лише замінити в усіх командах утиліту `tofu` на `terraform`.

Спочатку необхідно виконати команду для ініціалізації OpenTofu,
яка завантажить провайдерів, що використовуються в конфігурації,
а також створить інші файли, необхідні їй для роботи.

```console
$ tofu init
```

Також хорошою ідеєю буде переглянути конфігурацію та, за потреби,
змінити визначені у ній параметри або змінні. Значення змінних
можна вказати у самій конфігурації, створивши файли з розширенням
`.tfvars`, або під час виконання команди для запуску проекту.


## Як розгорнути?

Для розгортання визначеної у конфігурації інфраструктури,
користуючись послугами визначеного в конфігурації хмарного
провайдера, необхідно використати наступну команду:

```console
$ tofu apply
```

Якщо необхідні змінні (див. далі по тексту) не були визначені,
OpenTofu запропонує ввести для них значення вручну. OpenTofu
створить віртуальний приватний сервер, а після цього, виведе
у термінал його IP-адреси (4-ї та 6-ї версії).

Як тільки буде отримана публічна IP-адреса створеного сервера,
буде автоматично виконаний плейбук Ansible, визначений
за допомогою змінних. (В нашому випадку має використовуватись 
плейбук з [цього репозиторію](https://github.com/wadofan/mage-ansible-playbook)).


## Як "згорнути"?

Щоб видалити хмарну інфраструктуру, визначену в конфігурації,
необхідно використати наступну команду:

```console
$ tofu destroy
```


## Перелік змінних

Найважливішими змінними в даному проекті є `hcloud_token`,
що містить токен для доступу до API хмарного провайдера
(в нашому випадку Hetzner), а також `primary_ssh_key`, що
містить назву SSH-ключа, який буде використовуватись для
доступу до створеного сервера.

Для налаштування парамертів сервера можуть використовуватись
наступні змінні:

| Назва                | Опис                                                      |
| :------------------- | :-------------------------------------------------------- |
| `hetzner_datacenter` | ЦОД в хмарі Hetzner (наприклад, "nbg1-dc3" або "hil-dc1") |
| `hetzner_image`      | Образ ОС для сервера в хмарі Hetzner (наприклад, "ubuntu-22.04") |
| `hetzner_location`   | Локація в хмарі Hetzner (наприклад, "nbg1" або "hil")     |
| `hetzner_vps_type`   | Тип сервера в хмарі Hetzner (наприклад, "cx22")           |

Для автоматизованого запуску плейбука Ansible були
створені наступні змінні:

| Назва                   | Опис                                                |
| :---------------------- | :-------------------------------------------------- |
| `ansible_playbook_file` | Назва файлу плейбука Ansible                        |
| `ansible_remote_user`   | Ім'я користувача для доступу до віддаленого сервера |
| `ansible_ssh_key`       | SSH-ключ для доступу до віддаленого сервера         |
| `ansible_working_dir`   | Робоча директорія для Ansible (директорія, що містить плейбук) |
